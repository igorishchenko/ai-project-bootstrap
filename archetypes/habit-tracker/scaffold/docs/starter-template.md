## What got scaffolded

- **Schema** — `supabase/migrations/20260807120000_habit_tracker_schema.sql`:
  `habits` and `habit_checkins` tables, Row Level Security enabled on both,
  keyed on `auth.uid()`.
- **Sign-in** — `src/features/auth/` + `src/hooks/auth/useAuth.ts`: email
  magic-link, no password. `App.tsx` shows `SignInScreen` until a session
  exists.
- **Habits** — `src/features/habits/`: `habitsClient.ts` (the only file that
  queries Supabase directly), `streak.ts` (pure date logic), `useHabits.ts`
  (the hook every screen reads from), and two screens
  (`HabitListScreen`, `AddHabitScreen`).
- **`App.tsx`** — the root component: `ThemeProvider` (from the `dark-theme`
  module) wrapping a sign-in gate wrapping simple local-state screen
  switching. No router is wired in — see below.

## Before you run it

1. **Apply the migration.** Locally: `npx supabase start` then
   `npx supabase db reset`. Against a real project: `npx supabase link
   --project-ref <ref>` then `npx supabase db push`. See `docs/setup.md`'s
   Supabase section for the full first-time setup.
2. **Set the two Supabase env vars** in `.env` — `EXPO_PUBLIC_SUPABASE_URL`
   and `EXPO_PUBLIC_SUPABASE_ANON_KEY` (`.env.example` already lists them).
3. **Configure the magic-link redirect before shipping.** Without it,
   Supabase falls back to a browser confirm page instead of returning to
   the app — see the `TODO` in `src/features/auth/authClient.ts`.

Then: `npm install && npm run start` (or `npm run ios`/`npm run android`).

## What's deliberately not here

- **No router.** This generator never scaffolds one (see
  `technologies/react-native/architecture.md`) — `App.tsx`'s screen-switch
  is a placeholder to replace with real navigation, not the intended
  long-term shape.
- **No onboarding flow, payments, or notifications.** The `onboarding`,
  `revenuecat`/`stripe`, and notification modules all compose cleanly with
  this stack via `ai-project-bootstrap add <id>` — they're just not
  bundled by default, to keep the starter's first-run surface small.
- **Streaks are computed client-side**, from the check-in dates already
  fetched for the list screen — not a SQL window function. Simple and
  correct at the scale a starter app runs at; revisit if `listCheckins`
  ever needs to scale past "one user's own habits."
